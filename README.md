# Инквайри — образовательная платформа с ИИ-генерацией и сократическим ассистентом

Реализация по ТЗ v1.1 (MVP). Закрытая платформа онлайн-обучения для **научного исследования критического мышления**: ИИ генерирует тесты и практические задания, а **сократический чат-ассистент** ведёт студента к ответу наводящими вопросами, никогда не раскрывая ответ сам, и оценивает ход рассуждений.

> Слоган продукта: **учиться — значит задавать правильные вопросы.** Отсюда и визуальная идентичность: продукт буквально считает вопросы (индикатор «оставшиеся реплики»), а ассистент помечается знаком `?`.

## Архитектура

Монорепозиторий (npm workspaces):

```
packages/shared      @edu/shared — контракты: enums, константы, Zod-схемы вывода LLM (Прил. B/C/D)
apps/backend         Node.js + Fastify + TypeScript + Prisma (PostgreSQL) + BullMQ (Redis)
apps/frontend        React + TypeScript + Vite + Tailwind + TanStack Query + react-i18next
```

Ключевые принципы (§9.3 ТЗ):

- **Провайдер-агностичный ИИ** — весь доступ к модели через `apps/backend/src/llm/gateway.ts` (единственная точка выхода данных наружу).
- **Серверная авторитетность** — токен-бюджет, лимит реплик, вердикт, прогресс считаются только на сервере.
- **Приватность на границе (DP-5)** — псевдонимизация в LLM-шлюзе: наружу не уходят email/имя, только псевдо-ID.
- **Асинхронность** — генерация материалов через очередь BullMQ, не блокирует UI.
- **Расширяемость** — типы вопросов, языки, типы оценивания добавляются без ломки схемы.
- **Отслеживаемость** — сквозной `EventLog` + сохранение параметров ИИ-операций (модель/промпт/режим) для воспроизводимости.

### Ядро — сократическая оркестрация (`apps/backend/src/llm/orchestrator.ts`)

Режим по умолчанию — **двухвызовный «тьютор + судья»** (§5.4):

1. **Судья** видит эталон/рубрику → возвращает `student_reached_answer` + оценки рубрики (0..3).
2. **Тьютор** НЕ видит эталон (главный барьер утечки) → генерирует краткую наводящую реплику (потоково, SSE).
3. Сервер применяет правила: достигнут ответ → `PASSED`; исчерпан лимит реплик или токен-потолок → `FAILED`; иначе — реплика уходит студенту.

Четыре уровня защиты «не раскрывать ответ»: изоляция эталона · дизайн системной инструкции · пост-проверка на утечку (`leakDetector.ts`) · краткость реплик. Однокальный режим (`SINGLE_CALL`) доступен как опция оптимизации стоимости.

## Быстрый старт

### 1. Требования
- Node.js ≥ 20, Docker (для Postgres + Redis).

### 2. Инфраструктура
```bash
cp .env.example .env          # заполните секреты; LLM_PROVIDER=mock работает без ключей
npm install
npm run infra:up              # поднимает Postgres и Redis (docker compose)
```

### 3. База данных
```bash
npm run db:generate           # prisma generate
npm run db:migrate            # создать схему (prisma migrate dev)
npm run db:seed               # демо-данные (курс, пользователи)
```

### 4. Запуск
```bash
npm run dev:backend           # API на http://localhost:4000 (+ воркер генерации в dev)
npm run dev:frontend          # SPA на http://localhost:5173
```

### Демо-входы (после сида)
| Роль | Email | Пароль |
|---|---|---|
| Администратор | `admin@edu.kz` | `Admin123!` |
| Менеджер курсов | `manager@edu.kz` | `Manager123!` |
| Студент | `student@edu.kz` | `Student123!` |

> `LLM_PROVIDER=mock` — детерминированный оффлайн-режим: генерация и диалог работают **без реальных вызовов LLM и без передачи данных наружу**. Для реальной модели задайте `LLM_PROVIDER=anthropic|openai` и ключ.

## LLM-провайдеры (§5.1)

Провайдер выбирается через `LLM_PROVIDER`; модели под задачи — раздельно (`LLM_MODEL_GENERATION`, `LLM_MODEL_DIALOG`, `LLM_MODEL_JUDGE`). Кандидаты по ТЗ: OpenAI mini-класс (надёжный казахский), Claude Haiku-класс (следование инструкциям), Gemini Flash-класс (дёшево). **Финальный выбор — по итогам пилота** на реальном казахскоязычном контенте (обязательный выход: модель, режим оркестрации, таблица токен-потолков по языкам).

## Приватность и правовые блокеры (§13) — ВАЖНО

Эти пункты — **организационные/правовые**, вне кода, но критичны для старта сбора данных:

- **DP-2 [БЛОКЕР]** — локализация ПДн в РК: БД физически в Казахстане (или согласовать с юристом). В `docker-compose.yml` — только dev-инфраструктура.
- **DP-5 [БЛОКЕР]** — передача данных внешней LLM: технически реализована псевдонимизация в шлюзе; требуется договор no-training/zero-retention + DPA и юридическое заключение до старта этапов 4–5.
- **FR-R.6 / DP-3** — текст согласия готовит исследовательская/правовая сторона; версия задаётся в `RESEARCH_CONSENT_VERSION`.
- **DP-4** — одобрение этического комитета/IRB до сбора данных.

См. также `COMPLIANCE.md` — построчное соответствие требованиям ТЗ.
